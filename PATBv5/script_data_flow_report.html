PATBv5 Script Data Flow Report

This report compares the PowerShell wrappers in PATBv5 and shows, for each one, where it extracts data from, what controls or filters it applies, and where it saves results.

Scope: 5 PowerShell scripts
Support file checked: scripts/build_fresh_cohort.ts
Report file: PATBv5/script_data_flow_report.html

Quick Summary

Script Primary Data Source Control / Decision Logic Where Results Go
legacy/checker_old.ps1 Either a direct .jsonl path passed as SessionID or a resolved file in ..\polydb\telemetry\sessions. Chooses between explicit telemetry path vs session-id lookup; then runs four commands in sequence. No file output of its own. Results only print to console.
checker.ps1 Same telemetry resolution behavior as legacy/checker_old.ps1. Same command chain, plus try/catch/finally around execution and history recording. Writes run metadata to checker_history.json; command results still go to console.
legacy/run-batch_old.ps1 Reads session IDs from sessions.txt, then maps each ID to a telemetry file in ..\polydb\telemetry\sessions. Parses timestamp from the telemetry filename, sorts sessions chronologically, then invokes the checker for each. Does not save batch output itself. It passes -OutputFile results.md, but the called checker scripts do not define that parameter.
run-batch.ps1 Reads session IDs from sessions.txt; optionally reads checker_history.json to skip already analyzed sessions. Per-session loop, optional skip cache, optional -StopOnError, captures all checker output streams, then classifies session by checker process exit code. Appends full output and summary lines to batch_checker_results.log; checker subprocess also updates checker_history.json.
run-fresh-batch.ps1 Starts by building a fresh cohort from telemetry sessions via npm run cohort:fresh, then reads sessions_fresh_comparable.txt. Controls cohort generation with Since, Mode, and Strategy, then forwards the resulting list into run-batch.ps1. Cohort builder writes sessions_fresh_comparable.txt and sessions_fresh_comparable_report.json; batch phase writes to batch_checker_results.log and checker_history.json.

Per-Script Details

legacy/checker_old.ps1

  • Extracts data from: ..\polydb\telemetry\sessions, or from a direct telemetry file path if the supplied argument already points to a .jsonl file. Source resolution is implemented at lines 5 and 17-35.
  • Control: If the argument ends with .jsonl or matches an existing path, it uses that path directly. Otherwise it searches the sessions directory for *__{SessionID}.jsonl, sorts descending by filename, and picks the first match at lines 23-26.
  • Commands executed: tests/entry_ratio.test.ts, validate_signal_modules.ts, analyze_trades.ts, and live_readiness.ts via the npm scripts shown at lines 39-42.
  • Saves results to: Nowhere. It prints the target and all command output to the terminal only at lines 45-57.

checker.ps1

  • Extracts data from: The same places and with the same lookup logic as legacy/checker_old.ps1, at lines 5, 68-87.
  • Control: Same four-command sequence at lines 90-93, wrapped in try/catch/finally at lines 104-119.
  • Extra control file: Reads and rewrites checker_history.json through Read-CheckerHistory and Write-CheckerHistory at lines 9-56.
  • Saves results to: checker_history.json, storing sessionId, timestamp, target, and a coarse status string at lines 46-55 and 114-118. Command analysis output still only goes to stdout.

legacy/run-batch_old.ps1

  • Extracts data from: sessions.txt at line 22 and telemetry files under ..\polydb\telemetry\sessions at lines 7 and 26-27.
  • Control: Uses the filename prefix timestamp if present, otherwise falls back to file last-write time at lines 9-18 and 29-31. Sessions are sorted by that derived time at line 41.
  • Execution flow: Iterates the ordered sessions and calls the checker once per session at lines 48-50.
  • Saves results to: No batch-owned output file. It passes -OutputFile results.md to the checker at line 49, but neither checker.ps1 nor legacy/checker_old.ps1 defines an OutputFile parameter, so this script does not actually wire result saving through the checker.

run-batch.ps1

  • Extracts data from: sessions.txt by default at lines 12-16 and 33, and optionally checker_history.json at lines 20 and 40-52 to build a skip cache.
  • Control: Optional -IncludeAlreadyAnalyzed toggles use of the history skip list. Optional -StopOnError aborts after the first non-zero checker exit at lines 140-144.
  • Session status rule: It captures all output from checker.ps1 at line 106, but marks batch PASS/FAIL strictly from the checker process exit code at lines 114-121.
  • Saves results to: Appends raw per-session checker output plus batch summaries into batch_checker_results.log at lines 63, 89-94, 131-138, and 167-173. The checker child process separately saves history into checker_history.json.

run-fresh-batch.ps1

  • Extracts data from: It does not read telemetry files directly. It first launches npm run cohort:fresh with Since, Mode, and Strategy at lines 1-17 and 24.
  • Control: After cohort generation succeeds, it reads the resulting sessions_fresh_comparable.txt list at lines 11 and 35, then hands that list to run-batch.ps1 at lines 41-55.
  • Fresh cohort rules: The underlying builder reads every .jsonl in ..\polydb\telemetry\sessions by default, scans JSONL events, and filters by date, mode, strategy, raw momentum coverage, Monte Carlo coverage, and zero-signal coverage in scripts/build_fresh_cohort.ts lines 39-53, 128-179, 185-223, and 233-257.
  • Saves results to: Cohort stage writes sessions_fresh_comparable.txt and sessions_fresh_comparable_report.json in build_fresh_cohort.ts lines 50-52 and 256-293. The subsequent batch stage saves into batch_checker_results.log and checker_history.json.

Controls Used By The Fresh Cohort Builder

Telemetry Source

scripts/build_fresh_cohort.ts defaults to ../polydb/telemetry/sessions as its session directory at lines 39-40.

CLI Filters

Supported controls include --since, --mode, --strategy, --sessions-dir, --out-file, and --report-file at lines 42-88.

Event Fields Read

It inspects bot.startup, bot.startup_config, signal.momentum, signal.montecarlo, trade.signal_accepted, trade events, and feed.fallback at lines 147-179.

Inclusion Criteria

A session is excluded if it fails date, mode, strategy, raw momentum coverage, Monte Carlo presence, or useful coverage checks at lines 185-223.

Important Findings

run-batch.ps1 does not judge “readiness” directly. It only checks whether checker.ps1 exited with code 0. A session can therefore be counted as batch PASS even when the captured checker output contains LIVE readiness verdict: NOT READY.
legacy/run-batch_old.ps1 appears partially stale. It passes an -OutputFile argument to the checker, but the current checker scripts only accept SessionID. That means result-file handling is not implemented through this path.
Most actual persistence happens in three files: checker_history.json for run history, batch_checker_results.log for batch console capture, and the fresh cohort pair sessions_fresh_comparable.txt plus sessions_fresh_comparable_report.json.
