# ===================================================== 


You are fixing bugs in a Polymarket trading bot written in TypeScript.
The bot trades BTC 5-minute Up/Down markets on Polymarket using the CLOB v2 API.

## Files involved
- src/trade/decision.ts  — entry and exit logic
- src/trade/trade.ts     — order execution
- trade.toml             — strategy configuration

---

## BUG 1 — inExitRange causes immediate sell after every buy [CRITICAL]

In decision.ts, the trade_4 exit logic for both UP and DOWN positions contains:

  if ((this.upSellPrice >= trade4.take_profit_price || inExitRange)
      && secondsToClose > trade4.min_seconds_to_close) {
    await this.sellUpToken();
    break;
  }

The variable `inExitRange` is computed as:
  const exitRanges = trade4.exit_price_ratio_range;
  const inExitRange = exitRanges.some(([min, max]) =>
    up_price_ratio >= min && up_price_ratio <= max
  );

Where `up_price_ratio = Math.abs(this.upBuyPrice - 0.5) / 0.5`

With config `exit_price_ratio_range = [[0.0, 0.52], [0.86, 1.0]]`:
- The range [0.0, 0.52] maps to buy prices 0.24–0.76 (the entire normal market range)
- So inExitRange = true on virtually every tick
- The bot sells immediately after buying on the next decision cycle

FIX: Remove `|| inExitRange` from both the UP and DOWN exit conditions.
Change:
  if ((this.upSellPrice >= trade4.take_profit_price || inExitRange) && ...)
To:
  if (this.upSellPrice >= trade4.take_profit_price && ...)

Do the same for the DOWN case with `this.downSellPrice`.
Also remove the `inExitRange` variable declaration entirely as it is no longer used.

---

## BUG 2 — Stop loss fires on garbage orderbook ticks [CRITICAL]

The orderbook frequently produces stale/illiquid snapshots where:
  downSellPrice = 0.01, downBuyPrice = 0.99, spread = 0.98

When this happens, `downSellPrice (0.01) <= stop_loss_price (0.50)` fires the
stop loss on noise, not real price movement.

In decision.ts, the current stop loss checks are:
  if (this.upSellPrice <= trade4.stop_loss_price) { ... }
  if (this.downSellPrice <= trade4.stop_loss_price) { ... }

FIX: Add a spread validity guard before each stop loss check.
Only fire the stop loss if the orderbook snapshot looks real (spread ≤ 0.20):

  // UP stop loss
  const upSpreadValid = (this.upBuyPrice - this.upSellPrice) <= 0.20;
  if (upSpreadValid && this.upSellPrice <= trade4.stop_loss_price) {
    ...
  }

  // DOWN stop loss
  const downSpreadValid = (this.downBuyPrice - this.downSellPrice) <= 0.20;
  if (downSpreadValid && this.downSellPrice <= trade4.stop_loss_price) {
    ...
  }

## BUG 3 — Sell execution at garbage prices [CRITICAL]

In trade.ts, both sellUpToken() and sellDownToken() execute sell orders even
when the orderbook snapshot is clearly invalid (e.g. sellPrice = 0.01 with
spread = 0.98). In the previous live session, this placed a resting GTC order
at 0.01 which locked all tokens for the rest of the market.

FIX: Add a spread guard at the top of the live sell path in both
sellUpToken() and sellDownToken(), before any order is placed.

For sellDownToken(), add after the existing balance checks:
  const downSellSpread = this.downBuyPrice - this.downSellPrice;
  if (downSellSpread > 0.20) {
    console.warn(`⚠️  Skipping sell: stale snapshot | spread=${downSellSpread.toFixed(2)} | sellPrice=${this.downSellPrice}`);
    await writeTelemetryEventSafe("trade.exit_skipped_stale_snapshot", {
      strategy: globalThis.__CONFIG__.strategy,
      side: "DOWN",
      downBuyPrice: this.downBuyPrice,
      downSellPrice: this.downSellPrice,
      spread: downSellSpread,
    });
    return false;
  }

Apply the same pattern in sellUpToken() using upBuyPrice - upSellPrice.

## BUG 4 — Polygon RPC eth_getLogs timeouts [OPERATIONAL]

Logs show repeated errors:
  Market loop error: could not coalesce error
  { "code": -32002, "message": "request timed out" }
  method: "eth_getLogs"

These are Polygon RPC timeouts when watching for on-chain events.
They occur mid-trade and could cause missed exits.

FIX: Wrap all eth_getLogs / Polygon RPC calls in a try-catch with a
timeout guard. If the RPC call fails with code -32002 or UNKNOWN_ERROR,
log a telemetry event and skip that cycle rather than crashing the market loop.

Also: consider switching to a more reliable RPC provider such as:
- Alchemy (https://polygon-mainnet.g.alchemy.com/v2/YOUR_KEY)
- QuickNode
- Ankr public endpoint: https://rpc.ankr.com/polygon

The current RPC endpoint appears to be the default public one which
rate-limits and times out under load.

## BUG 5 — entry_price_ratio window is too narrow [CONFIG]

In trade.toml, `entry_price_ratio = [0.10, 0.28]`

The formula in decision.ts is:
  up_price_ratio = Math.abs(this.upBuyPrice - 0.5) / 0.5

So [0.10, 0.28] only allows buy prices in the range 0.55–0.64 (a 9-cent window),
causing ~491 rejections per session. This conflicts with min_entry_price = 0.52
which allows prices from 0.52 — those are always rejected by the ratio check.

FIX in trade.toml:
  entry_price_ratio = [0.10, 0.36]   # allows prices 0.55–0.68
  min_entry_price   = 0.55           # align with ratio lower bound
  max_entry_price   = 0.68           # align with ratio upper bound

## BUG 6 — max_rtt_ms is below observed average RTT [CONFIG]

In trade.toml, `max_rtt_ms = 300`
Telemetry shows avg RTT = 322ms, causing 91 unnecessary rejections per session.

FIX in trade.toml:
  max_rtt_ms = 500
